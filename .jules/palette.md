## 2024-06-16 - Programmatic Labeling and ARIA in React Components
**Learning:** When building complex React components with multiple input types (ranges, color pickers, specific number fields like CMYK), native `<label>` tags are often placed visually next to the `<input>` elements but fail screen reader accessibility if `id` and `htmlFor` attributes are omitted. Furthermore, native `<input type="color">` and text inputs acting as hex codes or identifiers (like "New Kit Name") are frequently left without `aria-label`s, rendering them ambiguous for assistive technologies. Additionally, complex action cards (like `<motion.button>`) need comprehensive `aria-label`s that consolidate their title, description, and shortcut keys for effective screen reader use.
**Action:** Always verify that `<label>` elements have a strict `htmlFor` mapping to an `<input>`'s `id`. For inputs without a visible textual label (or those handling complex formats like hex codes), enforce the use of descriptive `aria-label` attributes. When composing interactive cards, aggregate key textual information into a single `aria-label` to provide complete context.
